# 📋 Технический план монтажа системы точного времени для отелей Кубы

## 🎯 Цели проекта

**Основная цель:** Обеспечить высокоточную (до ±50 нс по PTP, ±10 мс по NTP), автономную и безопасную синхронизацию времени в трёх ключевых объектах сети Meliá на Кубе с централизованным мониторингом.

**Технические цели:**
- Развёртывание распределённой архитектуры Grand Master PTP серверов
- Обеспечение независимости от внешних NTP-серверов
- Внедрение централизованного мониторинга через Shiwa Management Platform
- Создание резервной системы мониторинга в офисе Гаваны с Elastic Database и Grafana

```
- Передача логов и метрик в офис РФ для анализа
```

**Настройка PTP (IEEE 1588):**
- **Режим:** Grand Master (BMC algorithm)
- **Профиль:** Default (может быть изменён на Telecom)
- **Domain:** 0 (стандартный)
- **Priority1:** 128 (высокий приоритет)
- **Announce interval:** 1 сек
- **Sync interval:** 1 сек

**Настройка NTP:**
- **Стратум:** 1 (первичный источник)
- **Режим:** Server mode для локальных клиентов
- **Broadcast/Multicast:** Включено для автоматического обнаружения
- **Ограничения:** Разрешить локальную подсеть, запретить внешние запросы

**Мониторинг и безопасность:**
- **Shiwa Management Platform:** Сбор метрик от всех Quantum Grand Master
- **Syslog:** Предпочтительно Syslog over TLS (TCP 6514) к SHIWA NETWORK MONITORING; при отсутствии поддержки — UDP 514
- **Elastic Database:** Хранение метрик и логов
- **Grafana:** Визуализация данных в реальном времени
- **SSH:** Доступ только из VPN подсети (локальной и РФ)
- **Firewall:** Блокировка внешних подключений к портам управления
- **VPN с РФ:** Шифрованное соединение для удалённого доступа и передачи данных

**3. Настройка маршрутизаторов:**
- Поддержка NAT/port forwarding
- Возможность настройки VPN (OpenVPN)
- Открытые порты для мониторинга (см. таблицу ниже)

**4. Безопасность:**
- Настройка фаервола для блокировки нежелательного трафика
- Поддержка VPN для безопасного удалённого доступа
- Мониторинг качества канала связи

## ✅ Критерии оценки результатов

### 1. Снижение инцидентов синхронизации
**Метрики:**
- Количество тикетов по проблемам времени: снижение на ≥80%
- Время расследования инцидентов: сокращение на ≥50%
- Точность временных меток в логах: ≤ ±1 секунда

**Методы измерения:**
- Мониторинг через SHIWA NETWORK MONITORING (количество событий синхронизации)
- Анализ логов систем безопасности и платежей
- Опрос ИТ-персонала через 1 месяц после внедрения

### 2. Повышение эффективности аудита
**Метрики:**
- Время корреляции событий между системами: ≤30 секунд
- Точность временной привязки: ≤ ±100 мкс между системами
- Успешность аудита кибербезопасности: отсутствие замечаний по времени

**Методы измерения:**
- Тестовые сценарии корреляции событий
- Автоматический мониторинг offset между серверами
- Аудиторские проверки через 2 месяца

### 3. Соответствие стандартам безопасности
**Метрики:**
- Независимость от внешних NTP-серверов: 100%
- Доступность системы синхронизации: ≥99.9%
- Соответствие требованиям PCI DSS по time sync

**Методы измерения:**
- Логи синхронизации (проверка источников времени)
- Мониторинг доступности сервисов
- Сертификаты compliance
